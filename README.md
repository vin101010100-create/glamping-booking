# Саха Глэмпинг

Сервис бронирования глэмпингов, баз отдыха и эко-отелей Республики Саха (Якутия).
Учебный проект по техническому заданию: Flask + SQLAlchemy + Bootstrap 5,
три роли, каталог с фильтрами, онлайн-бронирование и панель администратора.

---

## Возможности

### Гость
- Главная страница с поиском по локации, типу и датам.
- Каталог с фильтрацией по цене, расположению, типу и свободным датам.
- Страница объекта: галерея, удобства, стоимость, правила.
- Регистрация и авторизация.

### Клиент
- Всё, что доступно гостю.
- Создание бронирования с проверкой дат и занятости периода.
- Личный кабинет: редактирование данных, смена пароля.
- Список бронирований со статусами и суммой.
- Отмена бронирования до даты заезда.

### Администратор
- Дашборд с показателями сервиса.
- Добавление, редактирование, скрытие и удаление объектов.
- Загрузка фотографий и галереи.
- Просмотр всех бронирований и изменение статусов.
- Список пользователей и поиск по ним.

## Технологии

| Слой | Технология |
|------|------------|
| Язык | Python 3.12+ (проверено на 3.15) |
| Backend | Flask, Flask-Login, Flask-WTF (CSRF) |
| ORM | Flask-SQLAlchemy |
| Миграции | Flask-Migrate / Alembic |
| БД | PostgreSQL (в разработке допускается SQLite) |
| Frontend | Jinja2, HTML5, CSS3, JavaScript, Bootstrap 5.3, Bootstrap Icons |
| Конфигурация | python-dotenv |

Bootstrap и иконки подключены локально из `app/static/vendor/`, поэтому сайт
не зависит от CDN. Шрифты Google Fonts загружаются по сети, при их отсутствии
используются системные аналоги.

## Быстрый старт (Windows, SQLite)

В текущей папке уже есть локальная база `instance/glamping.db` с демо-данными
и настроенное виртуальное окружение `.venv`.

Самый простой способ — дважды щёлкнуть `start.bat`: он активирует окружение,
при необходимости создаст базу, откроет браузер и запустит сервер.

> После клонирования проекта с GitHub папок `.venv` и `instance/` не будет.
> В этом случае выполните полную установку из блока ниже.

Запуск вручную:

```powershell
cd glamping-booking

.\.venv\Scripts\Activate.ps1
flask --app run.py run --debug
```

Если хотите начать с нуля — удалите `instance/glamping.db` и выполните:

```powershell
flask --app run.py db upgrade
flask --app run.py seed-db
```

Полная установка с нуля (в том числе после клонирования):

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
flask --app run.py db upgrade
flask --app run.py seed-db
flask --app run.py run --debug
```

Сайт: http://127.0.0.1:5000

## Подключение PostgreSQL

1. Создайте базу:

```sql
CREATE DATABASE glamping;
```

2. Укажите строку подключения в `.env`:

```env
DATABASE_URL=postgresql+psycopg://postgres:postgres@localhost:5432/glamping
```

3. Примените миграции и заполните базу:

```powershell
flask --app run.py db upgrade
flask --app run.py seed-db
```

Драйвер `psycopg` (v3) уже включён в `requirements.txt`.
Если PostgreSQL ещё не установлен, проект продолжит работать на SQLite —
это удобно для демонстрации.

## Логика бронирования

1. Клиент выбирает даты на странице объекта.
2. Сервер проверяет формат дат, что заезд не в прошлом, выезд позже заезда,
   длительность не больше 60 ночей.
3. Выполняется запрос на пересечение с активными бронированиями
   (`pending` и `confirmed`):

```python
Booking.check_in < check_out AND Booking.check_out > check_in
```

4. При конфликте показывается предупреждение, запись не создаётся.
5. Иначе создаётся бронирование со статусом «Ожидает подтверждения».
6. Администратор переводит его в «Подтверждено», «Отменено» или «Завершено».

Каталог с выбранными датами аналогично исключает занятые объекты.

## Безопасность

- Пароли — только хеши Werkzeug (`generate_password_hash`).
- CSRF-защита всех POST-форм через Flask-WTF.
- `login_required` для личного кабинета и бронирования.
- `admin_required` для всех административных маршрутов.
- Проверка владельца при отмене бронирования (чужие брони — 403).
- Валидация всех входных данных на сервере (даты, цены, email, роли).
- Безопасный redirect после входа (защита от open redirect).
- Загрузка изображений: белый список расширений, уникальные имена,
  ограничение размера 8 МБ.
- SQL-инъекции исключены за счёт ORM.

Для production дополнительно рекомендуется: HTTPS, PostgreSQL, отдельный
секретный ключ, резервное копирование БД, проверка MIME и содержимого файлов,
а также ограничение частоты запросов.
